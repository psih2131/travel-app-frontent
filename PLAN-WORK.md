# План работы: Travel-проект (верстка → WordPress)

## Текущее состояние проекта

- **Стек верстки:** Vite, Handlebars, SCSS, Swiper, Fancybox, Flatpickr и др.
- **Страницы:** Главная, Туры / Тур, Блог / Пост, Направления, Гиды / Гиды (список), ЛК (профиль, заказы, стать гидом), Документы.
- **Уже есть:** модалки авторизации, регистрации, восстановления пароля, подтверждения; слайдеры, карточки туров/гидов/направлений, hero-поиск.

---

## Фаза 1. Довести фронтенд-верстку до конца

**Цель:** все страницы и сценарии есть в статике, можно показывать заказчику и потом резать в тему WP.

1. **Чек-лист страниц**
   - [ ] Главная (home) — доработать мелочи, адаптив, все блоки
   - [ ] Каталог туров (tours) — фильтры, сетка карточек, пагинация/подгрузка
   - [ ] Страница тура (tour) — программа, галерея, жильё, орг. детали, описание, форма заказа/заявки
   - [ ] Блог (blog) — список постов, возможно фильтр/теги
   - [ ] Пост (post) — контент, стили для контента из админки (`_wp-editor.scss` уже есть)
   - [ ] Направления (directions) — список направлений
   - [ ] Гиды (guides) — список гидов
   - [ ] Страница гида (guide) — профиль, туры гида
   - [ ] Личный кабинет (user-account): главная ЛК, заказы, один заказ, «стать гидом»
   - [ ] Документы (doc) — если нужна отдельная страница
   - [ ] Модалки: вход, регистрация, восстановление пароля, подтверждение — все состояния (ошибка, успех, загрузка)

2. **Общее по верстке**
   - [ ] Все ссылки и кнопки ведут куда нужно (якоря, заглушки страниц)
   - [ ] Формы: разметка, валидация на фронте (можно простую), состояния ошибок
   - [ ] Адаптив по макетам (мобилка, планшет, десктоп)
   - [ ] Доступность: фокусы, aria где нужно, клик по кнопкам/ссылкам

3. **Результат фазы 1**  
   Статичный сайт, который можно собирать через `npm run build`, все HTML-страницы готовы к переносу в тему WP.

## Фаза 2. Подготовка верстки к переносу в WordPress

**Цель:** минимизировать боль при переносе в тему.

1. **Структура и имена**
   - [ ] Разнести стили по логическим блокам/страницам (у вас уже частично: `_home.scss`, `_tours.scss`, `_blog.scss` и т.д.)
   - [ ] Вынести повторяющиеся блоки в отдельные partials (карточка тура, гида, поста, форма и т.д.) — у вас уже есть компоненты
   - [ ] Заложить единые классы под контент из админки (например `.wp-editor` / `.post-content`) — стили под редактор уже есть

2. **Пути и ассеты**
   - [ ] Картинки: решить, где хранить (тема, медиабиблиотека) и как обращаться (относительные пути или функции WP)
   - [ ] Шрифты, иконки, скрипты — папки, чтобы в теме было понятно, что куда копировать

3. **Документ для верстальщика/себя**
   - [ ] Краткий список страниц и соответствующих им partials/SCSS-файлов
   - [ ] Список компонентов (header, footer, карточки, модалки, формы) — что станет шаблонами/частями темы

**Результат фазы 2**  
Верстка готова к «нарезке» в тему: понятно, какой HTML/SCSS к какой странице WP относится.

## Фаза 3. Базовая установка WordPress и тема

**Цель:** поднять WP и сделать тему на основе вашей верстки.

1. **Окружение**
   - [ ] Установить WordPress (локально / хостинг)
   - [ ] Базовые настройки: язык, формат ссылок (ЧПУ), часовой пояс

2. **Тема**
   - [ ] Создать дочернюю тему или свою тему с нуля (рекомендуется своя тема под проект)
   - [ ] Перенести из сборки: стили (скомпилировать SCSS в CSS или подключать через build), скрипты, картинки, шрифты
   - [ ] Подключить стили и скрипты через `wp_enqueue_style` / `wp_enqueue_script`
   - [ ] Сделать базовую структуру: `header.php`, `footer.php`, `index.php`, `front-page.php`, `page.php`, `single.php`, `archive.php` и т.д., подключая ваши блоки (как сейчас partials)

3. **Главная и типовые страницы**
   - [ ] Главная (front-page.php) — ваша верстка главной
   - [ ] Страницы «О нас», «Контакты» и т.п. — обычные страницы WP (page.php) с вашим layout

**Результат фазы 3**  
Сайт на WP открывается с вашим дизайном, главная и простые страницы работают.

## Фаза 4. Кастомные типы записей (CPT) и таксономии

**Цель:** туры, гиды, направления, блог — как сущности в админке.

1. **Регистрация CPT и таксономий**
   - [ ] **Туры** (tours) — поля: название, описание, цена, даты, галерея, программа, жильё, орг. детали, связь с гидом/направлением
   - [ ] **Гиды** (guides) — фото, имя, описание, связь с турами
   - [ ] **Направления** (directions) — название, описание, картинка, количество туров (можно считать)
   - [ ] Таксономии: например «страна», «тип тура», «сложность» — привязать к турам
   - [ ] Блог — можно оставить стандартными записями (Post) + категории/теги

2. **Админка**
   - [ ] Удобные метабоксы или ACF/Carbon Fields для полей тура/гида/направления
   - [ ] Списки в админке: колонки (цена, дата, гид и т.д.), быстрые фильтры

**Результат фазы 4**  
В админке можно создавать туры, гидов, направления; на фронте выводить их списки и отдельные страницы (шаблоны single-tour.php, single-guide.php, archive-tour.php и т.д.).

## Фаза 5. Регистрация, авторизация, личный кабинет

**Цель:** кастомная авторизация и ЛК без «ломания» вашей верстки модалок и страниц.

1. **Регистрация и вход**
   - [ ] Форма регистрации: email, пароль, имя (и др. по ТЗ) — использовать ваши модалки (auth, registr)
   - [ ] Форма входа — модалка входа
   - [ ] Восстановление пароля — модалка recovery + письмо со ссылкой
   - [ ] Подтверждение email (если нужно) — модалка auth-confirm
   - [ ] Обработка через `wp_ajax_*` или REST API, ответы JSON для подстановки в верстку (успех/ошибка)

2. **Роли и права**
   - [ ] Роли: подписчик, клиент, гид, админ (по необходимости)
   - [ ] После входа — редирект в ЛК или на главную; в шапке показывать «Личный кабинет» / «Выйти»

3. **Личный кабинет**
   - [ ] Страницы ЛК (ваши user-home, user-orders, user-order, user-be-guide) доступны только авторизованным
   - [ ] Защита: проверка `is_user_logged_in()`, редирект на страницу входа при отсутствии авторизации
   - [ ] Данные профиля: вывод и редактирование (имя, email, аватар, телефон и т.д.) — форма в ЛК
   - [ ] Заказы: список заказов пользователя (если заказы хранятся в WP — кастомная таблица или CPT «заказ»)
   - [ ] «Стать гидом»: заявка (форма) → уведомление админу, смена роли или ручное одобрение

**Результат фазы 5**  
Пользователь может зарегистрироваться, войти, восстановить пароль; видит ЛК и свои заказы; может подать заявку «стать гидом».

**Цель:** от заявки/брони до отображения в ЛК.

2. **Фронт**
   - [ ] Форма заказа/брони на странице тура — отправка в админку и/или на почту
   - [ ] В ЛК — список заказов (ваша верстка user-orders, user-order), детали одного заказа

3. **Оплата (опционально)**
   - [ ] Интеграция платёжного шлюза (по ТЗ) — после того как заказы и ЛК уже работают

**Результат фазы 6**  
Заявка с тура сохраняется, отображается в ЛК и в админке.

## Фаза 7. Кастомная админка и доработки

**Цель:** удобная работа контента и при необходимости кастомный дашборд.

1. **Админка**
   - [ ] Убрать лишнее из меню WP (если не нужно: комментарии, стандартные записи и т.д.)
   - [ ] Свои пункты меню: Туры, Гиды, Направления, Заказы (если есть)
   - [ ] Настройки темы (Settings): контакты, соцсети, текст в футере — через Customizer или отдельная страница настроек

2. **Фронт**
   - [ ] Поиск: форма на главной (hero-search) — переход на страницу каталога туров с параметрами (направление, дата и т.д.)
   - [ ] Фильтры в каталоге туров — работа с таксономиями и метаполями (цена, даты)
   - [ ] Хлебные крошки — вывод с учётом CPT и таксономий
   - [ ] SEO: заголовки, мета-описания (можно плагин или свои поля)

3. **Производительность и безопасность**
   - [ ] Кэширование (плагин или серверное)
   - [ ] Защита форм (nonce), санитизация вводов, подготовленные запросы к БД

**Результат фазы 7**  
Админка заточена под проект; поиск и фильтры работают; сайт готов к наполнению и запуску.

## Рекомендуемые средства в WordPress

- **Типы записей и таксономии:** в коде темы (`register_post_type`, `register_taxonomy`) или плагин CPT UI.
- **Поля для туров/гидов:** ACF (Advanced Custom Fields) или Carbon Fields — удобные метабоксы в админке.
- **Формы (если не пишете сами):** Contact Form 7 / WPForms — только для простых форм; для регистрации/входа лучше кастом через `wp_login_form`, `wp_ajax_*` и ваши модалки.
- **Верстка в тему:** перенос собранных CSS/JS из Vite в тему, либо отдельный шаг сборки (npm run build → копирование в тему).

Если нужно, можно развернуть любую фазу в отдельный чек-лист по файлам и функциям WP (например, только фаза 5 — пошагово по хукам и шаблонам).
